**1. Problem statement and scope**
Write 2-3 sentences: *"Manual book tracking at the library causes lost records, long queues, and overdue books going unnoticed. We need an app to manage the catalog, borrowing, and returns."*
Then list **In scope** (search books, borrow/return, fines) and **Out of scope** (online payments, e-books).

**2. Stakeholders**
These are the people affected by the app: Members, Librarian, Admin, and possibly the school/institution.

**3. Requirements**
- **Functional** (what it does): "Members can search books by title," "Librarian can add or remove books," "System records due dates."
- **Non-functional** (how well it does it): search returns in under 2 seconds, passwords are encrypted, works on mobile.

**4. Five user stories + acceptance criteria**
Format: *As a [who], I want [what], so that [why].*
Example: *As a member, I want to search for books by title so that I can find what's available.*
- Acceptance criteria: Given I'm on the search page, when I type a title, then atching books appear with availability status.

Other story ideas: borrow a book, return a book, librarian adds a book, member views due dates.
